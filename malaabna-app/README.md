# ملعبنا — نظام إدارة النادي ومدرسة كرة القدم (تطبيق سطح مكتب)

تطبيق Windows حقيقي (مبني بـ Electron) يضم:
- شاشة **تسجيل دخول** و**إنشاء حساب** جديد قبل الدخول للتطبيق.
- أول حساب يتم إنشاؤه يصبح تلقائياً **مديراً**، وأي حساب لاحق يكون **عضواً**.
- خيار "تذكرني على هذا الجهاز" لتفادي إعادة تسجيل الدخول في كل مرة (30 يوماً).
- زر "تسجيل الخروج" أعلى التطبيق.
- يتضمن إدارة اللاعبين والحضور والإيصالات والمزامنة، مع تحسينات الجدولة الدورية ومتابعة الإصابات في الإصدار 3.8.1.

## ⚠️ مهم: لماذا لم أستلم ملف .exe جاهزاً؟
بيئة التنفيذ التي أعمل بها لا تملك اتصالاً بالإنترنت، بينما بناء مثبّت Windows عبر `electron-builder`
يحتاج تحميل حزمة Electron (~120 م.ب) وأدوات NSIS في أول مرة. لذلك جهزت لك **الكود المصدري الكامل
والجاهز**، وما عليك سوى تشغيل أمرين على أي حاسوب متصل بالإنترنت لإنتاج ملف `.exe` مطابق لأسلوب
"ملعبنا" الأصلي.

## خطوات البناء (على جهازك)

المتطلبات: [Node.js](https://nodejs.org) (نسخة 22.12 أو أحدث).

```bash
# 1) ادخل إلى مجلد malaabna-app وثبّت الإصدارات المثبتة في ملف القفل
npm ci

# 2) (اختياري) شغّل التطبيق أثناء التطوير
npm start

# 3) بناء مثبّت Windows (.exe)
npm run dist
```

بعد انتهاء الأمر الثاني، ستجد ملف التثبيت هنا:
```
dist/Malaabna-Setup.exe
```
وهو مثبّت NSIS (نفس النوع: Nullsoft/NSIS)،
مع اختصار على سطح المكتب وقائمة ابدأ.

> ملاحظة: إذا كنت تبني على macOS أو Linux ولا تحتاج مثبّت Windows، استعمل `npm run dist:dir` لتجربة
> التطبيق مباشرة بدون تثبيت (مجلد `dist/win-unpacked`).

### بيئة التطوير والاختبارات

يحتوي `package-lock.json` على إصدارات الاعتماديات المعتمدة؛ استخدم `npm ci` بدلاً
من `npm install` عند إعداد بيئة نظيفة. أوامر الفحص والاختبار:

```bash
npm run check       # فحص صياغة ملفات JavaScript
npm run test:unit   # اختبارات قواعد البيانات والمنطق
npm run test:ui     # فحوص واجهة المستخدم والإجراءات الآمنة
npm run test:pwa    # تحقق من التخزين والرجوع السريع للصفحات
npm run test:ocr    # تحقق من تحميل OCR المؤجل وملفات OCR المحلية
npm test            # تشغيل جميع مجموعات اختبارات التطبيق
```

لمزامنة نسخة الويب المنشورة بعد تعديل ملفات الواجهة، نفّذ من مجلد `server/`:

```bash
npm ci
npm run copy-web
npm run check
npm test
```

يُحمّل محرك Tesseract وقواميس اللغات محلياً عند بدء القراءة المحلية فقط. لا
تُضمّن ملفات WebAssembly والقواميس الكبيرة في قائمة التخزين الأولي للـ PWA؛
بعد طلبها تُخزّن مؤقتاً لتكون متاحة دون اتصال في الاستخدامات التالية.

### توقيع ملف Windows

لتقليل تحذيرات SmartScreen، ابنِ المثبّت على جهاز يملك شهادة Code Signing:
```powershell
$env:CSC_LINK="C:\secure\malaabna-code-signing.p12"
$env:CSC_KEY_PASSWORD="كلمة-سر-الشهادة"
npm run dist
```
لا تضع الشهادة أو كلمة سرها داخل المستودع أو الأرشيف. بدون شهادة، سيُبنى المثبّت
لكن قد يظهر تحذير من Windows عند أول تشغيل.

## أين تُخزَّن الحسابات والبيانات؟
- الحسابات (اسم المستخدم/كلمة السر المُشفّرة) تُخزَّن محلياً في:
  `%APPDATA%/malaabna/users.json` (كلمات السر مشفّرة بخوارزمية scrypt، لا تُخزَّن كنص صريح أبداً).
- في النسخة المثبّتة، إذا لم يتوفر التخزين الآمن لنظام التشغيل يتوقف التطبيق بدلاً من حفظ
  بيانات الحسابات أو الجلسات بصيغة نصية.
- رمز "تذكرني على هذا الجهاز" يُخزَّن أيضاً كـ hash (SHA-256) داخل `users.json`، والرمز الصريح
  يبقى فقط في `session.json` المحلي (بمثابة كوكي جهاز)، فلا يمكن انتحال الجلسة حتى لو اطّلع أحد على
  محتوى `users.json` وحده.
- كلمة السر يجب أن تكون **8 أحرف على الأقل** عند إنشاء الحساب.
- بعد **5 محاولات دخول فاشلة** بنفس اسم المستخدم، يُقفل الدخول لهذا الاسم لمدة **دقيقة واحدة**
  (الحماية في الذاكرة فقط، تُصفَّر عند إعادة تشغيل التطبيق).
- بيانات المدرسة والمرفقات المحلية مشفّرة في الإصدار 3.8.7: Electron يستخدم مفتاح نظام التشغيل، ونسخة الويب/PWA تطلب عبارة حماية محلية. عبارة الويب لا يمكن استعادتها؛ احتفظ بنسخة احتياطية قابلة للنقل مشفّرة بعبارة منفصلة. النسخ التلقائية مرتبطة بمفتاح الجهاز، وملفات CSV/Excel/PDF تظل غير مشفّرة. فعّل تشفير القرص الكامل وقفل مستخدم النظام؛ التشفير لا يحمي البيانات أثناء فتح التطبيق أو من برمجيات خبيثة تعمل ضمن الحساب.

## هيكل الملفات
```
main.js         → العملية الرئيسية لـ Electron (النوافذ + منطق تسجيل الدخول/الحساب)
preload.js      → جسر آمن بين الواجهة والعملية الرئيسية
login.html      → شاشة تسجيل الدخول / إنشاء حساب
app.html        → هيكل واجهة التطبيق
app.css         → التنسيق
finance.js     → قواعد احتساب الرسوم والتحقق المالي المشتركة مع الاختبارات
app.js          → منطق التطبيق (اللاعبون، الحضور، الإيصالات، المزامنة...)
package.json    → إعدادات المشروع والبناء (electron-builder)
build/icon.ico  → أيقونة التطبيق
```

## 🔄 المزامنة بين الأجهزة (خادم حقيقي يعمل محلياً)
تم استبدال آلية المزامنة القديمة (Google Apps Script / Firebase) بخادم Node.js حقيقي
مرفق في مجلد `server/` بجانب هذا المجلد. يعمل هذا الخادم على حاسوبك الخاص (يبقى
مُشغَّلاً)، ويُربط بالإنترنت مجاناً عبر **Cloudflare Tunnel** بدون فتح أي منفذ في
الراوتر. راجع `server/README.md` لدليل التشغيل والربط خطوة بخطوة.

بعد تشغيل الخادم والحصول على رابطه، افتح **الإعدادات ← المزامنة بين الأجهزة** داخل التطبيق:
1. ضع رابط الخادم.
2. من أول جهاز فقط: اضغط «إنشاء مساحة مزامنة جديدة» — سيولّد التطبيق رمز مدرسة وكلمة سر تلقائياً (احتفظ بهما).
3. أدخل نفس الرمز وكلمة السر في جهاز المدير فقط ثم اضغط «جلب آخر نسخة».
4. للموظفين والمدربين استخدم **حسابات الهاتف والدعوات** بصلاحيات محددة، ولا توزع سر مساحة المزامنة عليهم.

كلمة السر تُخزَّن على الخادم كـ hash فقط (bcrypt)، مع قفل مؤقت بعد محاولات دخول فاشلة متكررة،
على عكس الطريقة القديمة التي كانت تعتمد على مفتاح اختياري بسيط داخل رابط علني. ولحماية بيانات المدرسة،
تم تعطيل المزامنة الكاملة تلقائياً للحسابات المحلية غير الإدارية في نسخة سطح المكتب.

## تخصيص لاحق
- لتغيير اسم التطبيق: عدّل `productName` في `package.json`.
- لتغيير الأيقونة: استبدل `build/icon.ico` بأيقونة أخرى بنفس الاسم.
- لإتاحة عدة صلاحيات أدق (مدرب/محاسب...) بدل مدير/عضو فقط: يمكن التوسّع لاحقاً في `main.js`
  (حقل `role`) وربطه بنظام الصلاحيات الداخلي الموجود أصلاً في `app.html` (الإدارة مقابل المدرب).

## 🆕 الإصدار 3.8.25 — موثوقية التخزين المؤقت للـ PWA

- أضيفت الأيقونة المقنّعة وأيقونة iOS إلى cache shell. تبقى ملفات OCR الكبيرة خارج التثبيت وتُخزَّن عند أول استخدام.
- تُستثنى طلبات API والتنزيلات وروابط الاستعلام من التخزين؛ لا تُخزَّن الاستجابات الموسومة `private` أو `no-store`، ويحذف التحديث ذاكرات ملعبنا القديمة فقط.

- أصبحت `ALLOW_NULL_ORIGIN=false` افتراضياً. فعّلها فقط عند حاجة Electron للاتصال بخادم بعيد عبر `file://`، مع فهم أنها تقبل أصولاً معتمة أخرى.

## ✅ تحسينات الأمان والمزامنة (الإصدار الحالي)
- الإصدار 3.8.7: قاعدة المدرسة ومرفقاتها المحلية مشفّرة؛ Electron يستخدم مفتاح نظام التشغيل، ونسخة الويب/PWA تطلب عبارة حماية محلية. عبارة الويب لا يمكن استعادتها. النسخ التلقائية مرتبطة بالجهاز؛ التصدير اليدوي الكامل بصيغة `.malaabna` مشفّر بعبارة منفصلة وقابل للنقل. CSV/Excel/PDF والتقارير لا تُشفّر تلقائياً.
- **التسجيل العام مغلق** بعد إنشاء أول حساب (المدير)؛ المدير ينشئ باقي الحسابات من داخل التطبيق.
- **ملفات الحسابات والجلسة وقفل المحاولات مشفّرة** بمفتاح نظام التشغيل (DPAPI على ويندوز عبر `safeStorage`)،
  وتُرقّى الملفات القديمة النصية تلقائياً عند أول تشغيل. لا يمكن فكها من مستخدم ويندوز آخر أو جهاز آخر.
- **قفل محاولات الدخول يُحفظ على القرص** فلا يُصفَّر بإعادة تشغيل التطبيق.
- **أدوات المطوّر (F12) معطّلة في النسخة المثبّتة** ومنع فتح صفحات خارجية يقللان التلاعب العرضي.
  > نسخة سطح المكتب تقبل الآن تسجيل دخول المدير فقط، وتُرفض الحسابات محدودة الصلاحية عند الدخول أو الاستعادة التلقائية؛ كما يقتصر جسر تشفير/فك تشفير المخزن على المدير. فعّل دخول الهاتف للحسابات المحدودة كي يصفّي الخادم البيانات. هذا لا يحمي من شخص يسيطر على حساب Windows نفسه أو على جهاز المدير؛ استخدم حسابات نظام منفصلة وقفل الجهاز.
- **مزامنة بدمج ذكي على مستوى السجل** بدل استبدال النسخة كاملة، مع كشف التعارض في الخادم.
- **رابط الخادم الافتراضي:** https://sync.clubagaplus.ma
- تنظيف: فُصل `app.html` إلى ثلاثة ملفات (`app.html` / `app.css` / `app.js`).

## 🔧 إصلاحات الإصدار v3.1 (مراجعة أمنية)
- **كلمة سر المزامنة لم تعد تُرفع مع البيانات:** `syncSecret` و`syncCode` و`serverUrl` تُستثنى من النسخة المرفوعة، ويحذفها الخادم أيضاً إن وصلته من نسخة قديمة.
  ⚠️ إن كنتم استعملتم نسخة سابقة، فقد تكون كلمة السر القديمة محفوظة في `workspaces.json` والنسخ الاحتياطية: اضغطوا «تجديد كلمة السر» في الإعدادات.
- **حقن HTML عبر الصور:** كل مصادر الصور (الشعار، الختم، صور اللاعبين...) تمر عبر `safeImg()` التي تقبل `data:image` فقط.
- **CSP** في `app.html` و`login.html` (تقيّد المصادر، وتمنع الإطارات والنماذج الخارجية). ملاحظة: تمنع السياسة سمات الأحداث المضمّنة (`script-src-attr 'none'`)، بينما تبقى `unsafe-inline` للأنماط فقط.
- **مفتاح Gemini** يُرسل في ترويسة `x-goog-api-key` بدل الرابط، وإرسال الوثائق إلى Gemini صار للمدير فقط.
- **الخادم:** تشفير اختياري للبيانات والنسخ الاحتياطية بـ AES-256-GCM (ضع `DATA_KEY` في `.env`)، وقفل محاولات الدخول حسب (الرمز + IP) بدل الرمز وحده.

- **المتابعة التشغيلية:** أضيف مركز تنبيهات للوثائق القريبة من الانتهاء والمتأخرات والغيابات المتتالية، وصفحة صندوق يومي للمطابقة والإغلاق مع فرق الجرد.
